# Domain docs

## Before exploring

Read root `GLOSSARY.md`, if present, and relevant decisions in `docs/adr/`.
This repository uses a single-context layout.

If these documents do not exist, proceed silently. Domain-modeling work
creates them when terms or decisions are resolved; do not create empty
placeholders.

## Vocabulary

Use the glossary's defined terms in issues, proposals, hypotheses, and
tests. Reconsider invented terminology; flag genuine vocabulary gaps for
domain modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, naming the decision
and the reason to reopen it rather than silently overriding it.
